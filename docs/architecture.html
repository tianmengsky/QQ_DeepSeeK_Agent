dsh-qq-bridge · 系统架构图

QQ ⇄ DSH 桥接插件。以 cordis 插件形式运行在 DSH 宿主内：通过 HTTP 接收 OneBot v11 事件， 驱动一个 DSH Agent 会话（模型由宿主运行），再把模型产出的气泡/表情经 qq-mcp 子进程发回 QQ。 全部跨进程/跨重启状态落在共享 SQLite。
Node ≥ 24.10 cordis ~4.0.4 插件 OneBot v11 SQLite 持久化 MCP 子进程 (qq-mcp) 87 模块 · lib/
外部系统 / 进程边界 接入与传输 领域规则 会话与上下文 编排与业务 Agent 集成 提示词 记忆 投递 持久化

① QQ 客户端 / OneBot v11 接入端

go-cqhttp / SnowLuma 等。事件来源（消息、notice、request）与消息出口。桥接只说 OneBot 协议。

② DSH · Cordis 宿主

加载本插件，提供 webServer / sessionController，运行 cordis 框架并跑模型推理。

③ qq-mcp（独立进程）

MCP stdio 子进程，向 Agent 提供 QQ 发送/读取/管理工具；与桥接共享 SQLite 的 runtime_state 做交接。

每会话关键状态与机制

滑动窗口

别人的消息与自己的回复分别设上限（如 10 + 15），避免自言自语挤掉上下文。 trimWindow 裁剪。

清醒窗口 (speech)

成功发言后开 60s 窗口；窗口内未 @ 的群消息可跟聊。 activity.mjs 统一管理，落库可跨重载恢复。

心跳缓冲

没被点名的群消息进 pending 缓冲；心跳判定未读阈值/冷却后决定是否主动插话；消费即 ack，避免重载重复恢复。

Session 轮换

每 N 轮换新 DSH Session，让上下文长度恒定；桥接自拼人设+记忆+窗口。 context-overflow 触发丢弃+轮换。

串行化队列

每会话一条 Promise 链，禁止按"最后一段文本"猜回合，归属靠 rpcId/inbox 消费确认。

跨会话守卫

execution-scope 保证同一时刻只对一个会话发工具；active-conversation 键供 qq_say 校验。

幂等回执

reply-journal + outbox idemKey：发送结果跨重启可恢复，避免重复发或"回复被吞"。

记忆预算

memoryBlocks 去重+预算+渲染顺序；情景/事实/反思三档，提炼与反思与聊天解耦。
